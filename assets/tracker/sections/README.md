# Участки режима «Поехали»

`index.json` — каталог пользовательских маршрутов. Каждый физический участок хранится в отдельном JSON и может редактироваться независимо.

Обязательная часть файла участка сохраняет согласованный контракт `schema_version: "1.0"`:

- `elements[].start_m`, `stations[].km`, `km_start` и `km_end` используют официальный километраж из режимной карты;
- `speed` не извлекается из PDF: `established` остаётся `null`, списки ограничений — пустыми, `source` — `manual_required`;
- неподтверждённые места описываются в `flags_for_review`, а разрывы профиля — в `runtime.profile_gaps`;
- `signals` и `whistle_points` остаются пустыми, пока не будут перенесены и проверены вручную.

Расширения текущего WebApp находятся отдельно:

- `geometry.paths[].points` содержит офлайн GPS-геометрию;
- `chainage_m` — официальный километраж, `ordinate` — координата старого EMap;
- для совместимости выполняется `chainage_m = ordinate + 1000`, поэтому `runtime.coordinate_offset_m` равен `-1000`;
- `runtime.route_legs` задаёт порядок прохождения GPS-путей и не меняет физический профиль.

Маршрут Высокогорная — Новый Мир собран из нескольких участков: две альтернативы до Оунэ, общий участок Оунэ — Пивань и отдельный участок после сброса километража у Пивани. Это отражено в `index.json.routes[].variants` без смешивания несовместимых шкал в одном `elements[]`.

Проверка каталога:

```powershell
node scripts/validate-tracker-sections.mjs
```

## Импорт старых ЭК 0.6.9

Архивы из меню старого приложения преобразуются в этот же контракт отдельным
воспроизводимым конвертером:

```powershell
python scripts/import-ek-archives.py "D:\Загрузки\ЭК_Блокнот_машиниста_0.6.9_2026-08-30"
```

Конвертер сопоставляет профиль с GPS-секторами по километражу, переводит старую
ординату в официальный километраж (`chainage_m = ordinate + 1000`) и добавляет
маршруты в `index.json`. Все такие секции получают `status: "draft"` и
`profile_status: "legacy_ek_unverified"`. Скорости из старых XML намеренно не
переносятся: действующие ограничения должны быть внесены и подтверждены отдельно.

Валидатор проверяет ссылки каталога, обязательные поля, запрет автоматически заполненных скоростей, порядок элементов профиля, объявленные разрывы и согласованность GPS-координат.

## Когда участок можно перевести в `verified`

`status: "verified"` разрешён только после полной ручной сверки. Статус в `index.json` и в самом section-файле должен совпадать; маршрут не может переопределить его отдельно.

- профиль непрерывно покрывает весь участок, `profile_gaps` и `flags_for_review` пусты;
- все элементы и станции имеют `confidence: "verified"`, а `runtime.profile_status` равен `pdf_verified`;
- PDF provenance содержит SHA-256, число страниц и роль `authoritative_map_profile_verified`;
- GPS-геометрия прошла полный контрольный проезд и имеет `geometry.status: "field_run_verified"`;
- каждое маршрутное звено целиком покрывается GPS-точками своего пути.

Пока хотя бы одно условие не выполнено, участок остаётся `draft`: его можно выбрать вручную для теста, но приложение не выберет его автоматически.

## Направление движения и чётность

Направление по координатной оси и чётность поезда — независимые величины:

- маршрут между двумя найденными станциями задаёт движение в сторону роста или убывания км/пк;
- после начала поездки GPS подтверждает сторону движения по изменению проекции на линию;
- номер поезда задаёт только `ЧЁТ/НЕЧЁТ` и не имеет права разворачивать профиль;
- общий выбор `Авто / +КМ / −КМ` работает на любой ЭК без индивидуальной правки section-файлов;
- необязательное `even_coordinate_direction: 1|-1` можно публиковать только при наличии проверенной привязки чётности к координатной оси.

У импортов `ek069-*` такой привязки нет, поэтому движок намеренно не предполагает, что рост координаты всегда означает чётное направление.
