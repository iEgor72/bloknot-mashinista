# Установка самостоятельной PWA без повторного входа

Реализация: ветка `codex/pwa-install-handoff`, база `origin/main` / `31405eb`, shell v418.

## Пользовательский путь

В авторизованной Telegram Mini App кнопка «Установить на телефон» открывает внешний браузер через `Telegram.WebApp.openLink`. Сервер заранее готовит ссылку, чтобы вызов открытия выполнялся непосредственно в обработчике нажатия. Ссылка живёт 120 секунд. Если подготовка не успела или связь пропала, приложение предлагает повторить нажатие после подготовки; автоматических циклов открытия нет.

Страница `/install` обменивает код на cookie, затем отдельным запросом проверяет сохранение cookie. Только после проверки появляются установка или инструкция под текущую платформу. На Chromium используется `beforeinstallprompt`, если браузер его предоставил. На iOS показывается инструкция для системного меню. Событие `appinstalled` и запуск standalone отделены от простого принятия установочного диалога.

Если вход утрачен, существующий механизм запроса в боте используется с сохранением идентификатора на стороне исходного браузера/PWA. Возврат по focus/visibility и опрос видимой страницы завершают вход. Сообщение бота больше не предлагает открыть другую вкладку или Mini App.

## Сервер и хранение

- `POST /api/auth/install-handoff`: требуется действующая сессия. Возвращает `/install#code=...` и время истечения.
- `POST /api/auth/install-exchange`: принимает JSON с кодом. Однократно устанавливает HttpOnly cookie, не возвращает постоянный bearer в ссылке.
- SQLite migration 5: таблица `auth_install_handoffs`, 256-битный случайный код хранится как SHA-256. `DELETE ... RETURNING` атомарно погашает код, в том числе между процессами. После истечения код не принимается. Создание удаляет просроченные записи, глобальный предел — 5000.
- Ограничение выдачи — по пользователю; обмена — по клиенту. Запросы требуют JSON и отклоняют чужой Origin / cross-site Fetch Metadata.
- Код находится во fragment, очищается из адреса и не записывается в browser storage. Он является временным секретом: перехват/пересылка рабочей ссылки до погашения позволяет войти. Страница не содержит сторонних скриптов/аналитики, использует no-store, no-referrer, CSP и запрет встраивания.
- Существующие 30-дневные cookie и bearer сохраняются совместимыми. GET `/api/auth` продлевает сессию; недействительный bearer больше не исключает восстановление по cookie.

## Runtime и обновление

Браузер/PWA сразу восстанавливает собственную сессию. В Mini App остаётся приоритет проверенного Telegram initData. Сетевой сбой при фоновой проверке сохраняет локальную личность и данные, допускает повторную попытку. Ошибка первого входа по сети предлагает повторить проверку, а не заново переходить в Telegram.

`/install` и её JS/CSS обслуживаются worker по сети без кеширования. Shell v418 доставляет изменённые runtime-файлы существующим клиентам. Старый bootstrap v417 остаётся доступен. Manifest получил постоянный `id=/?app=v417`, совпадающий с неявным идентификатором предыдущего production manifest; дальше этот id нельзя повышать вместе с версией. `start_url` остаётся без секретов, scope — `/`.

Наличие ярлыка Telegram больше не скрывает пункт установки самостоятельной PWA в профиле.

## Проверка

- `npm run test:server`: одноразовость при конкурентном обмене, cookie restore со старым bearer, Origin, методы, заголовки, срок и сохранность кодов после переоткрытия SQLite; общие API/storage регрессии.
- `npm run smoke:pwa-install`: реальные локальные API и разные browser contexts; вход по одной cookie; повтор ссылки; запасной bot pairing с имитацией подтверждения в изолированной БД; iPhone-инструкция; mock событий установки; отсутствие ожидания Telegram в браузере; сохранение состояния при 503.
- `npm run smoke:sw-update`, `npm run smoke:local`, `npm run smoke:offline`: обновление shell, новая кнопка, офлайн-регрессии.
- Скриншоты: `artifacts/pwa-install/android-install.png`, `artifacts/pwa-install/iphone-install.png`.

Физическая установка не проверена: браузерные события и копирование cookie моделируются, это не запуск Telegram/iOS/Android на реальном телефоне. До публичного обещания «без повторного входа» проверить на Android Chrome и iPhone Safari: переход из Telegram, подтверждение установки, первый запуск с иконки, перезапуск, запуск после перезагрузки телефона, отмену установки и истёкшую ссылку. Проверить также клиента Telegram, который открывает ссылку во встроенном браузере; гарантировать принудительный выбор внешнего браузера на всех клиентах нельзя.

Деплой и перезапуск production в рамках этой реализации не выполнялись. Изменения находятся в отдельной рабочей копии; исходная папка с незавершёнными изменениями приложения не затронута.
