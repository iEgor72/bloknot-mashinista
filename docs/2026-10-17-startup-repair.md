# v420 startup and offline-cache repair

The iPhone showed an uninitialized shell in both Telegram and the installed PWA. Raising the nginx connection/burst limits removed observed 503 responses but did not restore the affected device. Subsequent requests included interrupted HTTP/2 bodies. The user confirmed the app previously worked with the same VPN.

The previous worker fetched the shell using unbounded Promise.all, repeated the same warmup for multiple registrar messages, and revalidated versioned code during every startup. Cache audits accepted empty code, and replacement deleted the working response before writing its replacement. Blocking CSS could prevent deferred service-worker registration, including the code needed for recovery.

v420 serializes warmups and limits background transfers to four, skips usable existing responses, serves versioned code directly from valid cache, rejects empty/HTML script and stylesheet bodies, and replaces entries atomically. CSS imports now share the version namespace. An inline watchdog can register the repair worker before deferred scripts run and reload a stalled shell once on takeover. It does not treat a visible but uninitialized application shell as a successful startup. The PWA id, localStorage keys, pending mutations, API envelopes and database schema are unchanged.

Validation: four worker regression tests; 28 server tests; service-worker update smoke; full offline smoke including poisoned empty CSS/JS repair, mixed-version self-repair and offline seeded shift restore. A separate mobile viewport browser test delayed CSS and observed automatic recovery in about 8.6 seconds. Another test verified local pending sentinel preservation through cache repair and offline reload. Real iPhone and its VPN remain a device-side confirmation.

Production origin is klyuchik-ru1 (201.51.30.200), systemd bloknot-mashinista.service, archive releases under /opt/bloknot-mashinista/releases with current symlink and persistent data at /var/lib/bloknot-mashinista. Some inherited ai-memory documents in this release still describe the historical PM2 environment; do not use that historical deployment path. Nginx limits were repaired separately with a protected configuration backup. Application release requires exact published commit, consistent SQLite backup, atomic symlink switch, targeted service restart, and public verification; retain the prior release for rollback.
