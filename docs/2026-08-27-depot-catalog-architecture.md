# Каталог дорог, дирекций, депо и пакетов «Поехали»

Статус решения: принято, первая версия реализована 2026-08-27.

## Зачем

ТЧЭ-9 — первый заполненный участок, но продукт не должен считать его единственным депо или владельцем всех маршрутов. Каталог отделяет организационную структуру от данных участков и позволяет постепенно добавлять другие депо без переделки идентификаторов и пользовательских данных.

## Модель

- `railway` — территориальная железная дорога. В каркасе заведены все 16 дорог сети.
- `traction_directorate` — административная дирекция тяги, связанная с дорогой отдельным идентификатором.
- `depot` — эксплуатационное локомотивное депо. Код вида `ТЧЭ-9` не считается уникальным по всей сети; стабильный id включает дорогу, код и место.
- `section` и `route` — повторно используемые данные пути из `assets/tracker/sections`. Они не принадлежат депо.
- `depot_pack` — подборка route/section для конкретного депо. Одни и те же участки в будущем могут входить в несколько пакетов.
- `service_arm` — пользовательское плечо обслуживания внутри `depot_pack`. Оно содержит один или несколько вариантов хода и ссылается на готовые карты по стабильному `tracker_map_id`.
- `source` — происхождение каждого утверждения и ограничения источника.

Связи депо с маршрутами являются многие-ко-многим через пакеты. Это важно для стыковых плеч, подмены бригад и общих участков соседних депо.

## Статусы и публикация

`legacy_unverified` означает только найденного кандидата: такое депо нельзя показывать пользователю как готовый пакет. `pack_available` требует существующего файла пакета. У пакета собственный статус; первый пакет ТЧЭ-9 имеет `pilot_draft`, потому что его участки пока `draft`.

Число 147 из отчётности РЖД хранится как ориентир полноты сети, а не как заявление, что в каталоге уже 147 подтверждённых записей.

## Пополнение

Новый пакет принимается только вместе с источниками, стабильным id депо и существующими route/section id. Автоматический валидатор проверяет ссылки между дорогами, дирекциями, депо, источниками и участками, уникальность плеч и существование каждого `tracker_map_id`. Он также запрещает помечать пакет полностью проверенным, если хотя бы один участок не имеет статус `verified`.

Профиль читает каталог по схеме `дорога → депо → пакет`, сохраняя канонические `railwayId` и `depotId` рядом со старым текстовым названием депо. Режим подготовки без GPS сначала показывает плечи выбранного пакета и только затем загружает профиль нужного маршрута. Конкретных проверок на ТЧЭ-9 в интерфейсе нет.

Пользователь не редактирует опубликованный пакет напрямую. Из профиля или выбора плеча он отправляет предложение депо, плеча и имеющихся материалов; сервер хранит заявку со статусом `new`, а общий каталог меняется только после редакторской проверки. Так пользовательское пополнение масштабирует покрытие, не превращая непроверенный ввод в данные безопасности для всех.
